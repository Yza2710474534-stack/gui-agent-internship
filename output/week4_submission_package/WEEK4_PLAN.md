# 第四周学习与开发计划

## 本周目标

把第三周已经分别验证的截图、OCR、模型规划、控制和完成条件连接为一个可暂停的实时循环。默认模式只预览动作；真实桌面模式必须显式开启，并且保留动作白名单、动作上限、逐步验证和结构化日志。

## 七天安排

1. 第一天：完成实时循环骨架、动作白名单、预览/真实两种模式和单元测试。
2. 第二天：接入 MSS 截图和 EasyOCR，统一观察结果格式，保留图片路径、尺寸和 OCR 证据。
3. 第三天：接入第三周模型接口，限制规划结果为结构化动作，不接受任意代码或 shell 命令。
4. 第四天：把浏览器搜索改成完整实时流程；每一步执行后重新截图并验证页面变化。
5. 第五天：加入暂停、停止、动作次数上限、异常恢复和超时日志；不自动发送消息、不执行删除操作。
6. 第六天：在 Mac 上做一次真实浏览器搜索复测，保存前后截图、OCR、动作日志和完成判定。
7. 第七天：回归全部测试，整理第四周周报、验收报告和代码包；明确真实运行边界。

## 第一天完成标准

运行：

```bash
./.venv/bin/python -m unittest -v tests.test_week4_realtime
```

应通过实时循环的预览、真实执行、完成验证、停止、异常边界和动作上限测试。默认 `mode="preview"` 不调用执行器。

## 安全边界

- `preview` 是默认模式，只生成一次待执行动作，不发送鼠标键盘事件。
- `live` 只接受 `click`、`type_text`、`scroll` 和 `wait` 四种动作。
- 输入动作只接受英文、数字和常用标点；不接受 shell、任意 Python 或删除命令。
- 每个动作都要经过验证；最终状态必须额外经过完成条件验证。
- 第四周真实复测优先使用浏览器搜索，消息流程只保存草稿，不自动发送。
